## 3. 去重后的 P0 合并清单（A ∪ B ∪ C 三方合并）

### P0-1【设计不自洽 · 完成判定不可落地】= A.P0-A + C.§4 + B.P0-2(第1段)

- **合并理由**：A 发现「信号1 无落地函数」（`opencode-client.js:623` 只认 assistant）；我（C）发现「信号1/信号2 布尔关系未定义」（`:625` 为 OR）；B 发现「`waitForSessionIdle:670` 短路分支归属未裁决」。三者是**同一个设计缺口的三个切面**：v2 §4.2 重写了「判定信号」，但**没有定义这些信号在既有代码结构里如何接线、如何组合**。
- **证据**：`tech-design.md:99-107` vs `opencode-client.js:623/625/670`；真机 F11（秒短路）+ F12（idle 是权威信号）。
- **必须裁决**：
  1. 信号1（idle 消息）**接入哪个函数**——扩展 `getLastAssistantProgress` 还是新增 `getSessionCompletion`？
  2. 信号1 与信号2 是 **AND 还是 OR**？（必须消除 `:625` 的 `|| streamed` 语义歧义）
  3. `:670` 的 `status==='idle'` 短路分支**保留还是删除**？V1/V2 是否分流？
- **阻塞判定**：**是**。不裁决 → 实现者必然猜测 → 误按 OR 实现则 R3 复活，误删短路分支则 V1 完成判定劣化。

### P0-2【数据丢失 · failed/超时被误判为成功】= A.P0-B + B.P0-2(第3段) + C.R11-2

- **合并理由**：A 发现「`failed`/`interrupted` 三态等价用于完成」；B 发现「超时（`completed:false`）仍置 `EXTRACTED` 并删 fork」；我的 R11-2 发现「idle+failed 不得误判成功」。三者共同指向 **`daemon.js:468-479` 的单一布尔判定**：`waited.completed` 为真即「✅ 复盘完成」+ `EXTRACTED`，而该布尔**无法区分「成功」「失败」「超时」**。
- **证据**：`daemon.js:468-479`（`if(waited.completed)` 三分支合二为一）、`:487-493`（finally 无条件删 fork）、`tech-design.md:100-101`（三态未区分）；OpenAPI 证实 `outcome` enum = `{succeeded, failed, interrupted}`。
- **必须裁决**：
  1. `succeeded` → `completed:true`；`failed`/`interrupted` → **独立状态**（不得为 `completed:true`）；
  2. 超时 → **置 `FAILED` 而非 `EXTRACTED`**，使超时会话可重试，杜绝静默腰斩；
  3. 若 `waitForSessionIdle` 返回签名 `{completed, waitedMs, finalStatus}` 无法表达三态，**须先改签名**并同步改 `daemon.js:468`。
- **阻塞判定**：**是**。这是唯一会造成**数据永久丢失 + 假状态**（标了 EXTRACTED 却从未抽取）的项，优先级最高。

### P0-3【设计已证伪 · 分页方案不可用】= A.P0-C + B.P0-1（V1 分支）+ 真机 F13

- **合并理由**：A 从 spec 推断「order+cursor 违背契约」；B 发现「V1 裸数组无 cursor，统一翻页会误伤 V1」；**真机 F13 已确证**：`order=asc&cursor=<c>` → **400**。故 v2 §4.3 分页设计**在 V2 上根本不可执行**，在 V1 上**无分支保护**。
- **证据**：真机 F13（400 `InvalidCursorError`）；`tech-design.md:110-112` 仅有「显式 order=asc + 循环 cursor.next」；`opencode-client.js:368`（`Array.isArray` 判 V1 形态）；`tests/test-host-client.js` 第 14 项（V1 消息路径回归基线）。
- **必须裁决**：
  1. **翻页只能只带 cursor、不带 order**（F13 唯一可行方式）；全程 desc，取「最新」= 第 1 页第 1 条；
  2. `readAllMessages` **必须按 version 分流**：V1 → 单次裸 GET（现行为保留，不传 limit/order）；V2 → 仅 cursor 翻页 + 页数/条数硬上限；
  3. `listCandidateSessions` 分页**单独写明**（两端点契约不同）。
- **阻塞判定**：**是**。分页是修复 R2（数据判定错位）的核心手段，而该手段**已被真机证伪**；V1 分支缺失会造成 V1 抽取静默丢失。
