**我的量化错误（必须撤回）**：

### ②.7 我的 R8（凭据外发）—— **[坚持]（维持 P1 遗漏项）**

- F13/F14 **不影响 R8 判断**（二者与认证/探测无关）。
- 复核代码：`opencode-client.js:76-93` `probe` 的循环为 `for (const withAuth of [true, false])` —— **确为先带凭据再裸探**（实读确认），与 v1 design-review.md:32 记的"既有设计"一致。
- **"先带凭据探"vs"先裸探 401 再带"在真机确证 V2 无凭据即 401 的前提下，哪个更优？**
  - F1/F2：无凭据 `/api/info` → **401 + `WWW-Authenticate: Basic realm="Secure Area"`**。
  - **裁决："先裸探"更优。** 理由：401 + `WWW-Authenticate: Basic` 是**强特征**（证明该端口是受 Basic 保护的 HTTP 服务，且与 OpenCode 的认证模型一致）。先裸探可**在向无关本地服务外发凭据前完成初步识别**；只有确认是 Basic-保护服务后才带凭据。现设计"先带凭据"会向 netstat 枚举的**每一个**监听端口首发凭据，是纯负收益。
  - 唯一反例（需诚实标注）：若某个无关本地服务对无凭据请求返回 200 JSON 且恰好含 `version/pid/urls`，则裸探会误判——但此概率极低（ServerInfo 四字段 + v2 §4.1 收紧判据已挡）。
- **维持 R8 为遗漏项，级别 P1（非 P0）**：理由同 v1 裁决（"机制真实但前提严苛"），且 v2 **全文未提 R8**（三方均确认：A 的 :83、C 未单列、我的 :104）。**最低要求：v2 必须显式表态（修 / 记债独立工单），不可静默丢弃。**
