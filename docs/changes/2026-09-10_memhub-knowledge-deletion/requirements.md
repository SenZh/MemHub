# 需求规格说明书：支持手动删除记忆 (Requirements)

## 1. 业务背景与痛点
MemHub 在开发过程中通过 Agent 自动提炼、离线做梦或手动录入沉淀了大量工程知识卡片。
但在实际研发治理场景中，经常会出现以下诉求：
1. **脏数据治理**：测试或调试期间沉淀的临时卡片需要清理；
2. **提取纠错**：偶发的无价值或提炼不准确的卡片需要人工剔除；
3. **敏感信息清除**：若误记录了非公开业务机密，需提供彻底物理抹除手段。

目前系统仅支持沉淀与查询，缺失直接删除功能，导致用户无法对暗知识库进行人工干预与有效治理。

---

## 2. 核心功能需求 (Functional Requirements)

### 2.1 存储层原子级级联删除 (FR-DEL-1)
- **FR-DEL-1.1 事务级级联清除**：提供 `deleteKnowledge(id)` 接口，在单一 SQLite 事务内原子执行：
  - 从主表 `knowledge_items` 物理删除；
  - 从全文倒排虚表 `knowledge_fts` 物理清理（避免 FTS 幽灵命中）；
  - 从向量表 `knowledge_embeddings` 物理清理（避免向量余弦幽灵召回）。
- **FR-DEL-1.2 幂等与不存在校验**：若目标卡片 ID 不存在，返回 `{ success: false, notFound: true, message: "..." }`，不产生异常中断。

### 2.2 HTTP 服务端删除接口与安全门禁 (FR-DEL-2)
- **FR-DEL-2.1 RESTful 契约**：暴露 `DELETE /api/knowledge/:id`（并兼容 `POST /api/ops/delete` 或类似语义）；
- **FR-DEL-2.2 CSRF 门禁防御**：删除操作属于高危破坏性写操作，必须强制校验请求头 `X-MemHub-Request: 1`，彻底阻断跨站恶意删除。

### 2.3 WebUI 前端删除与防误触交互 (FR-DEL-3)
- **FR-DEL-3.1 详情抽屉删除按钮**：在 L2 详情 Modal 底部左侧提供高警示度的「🗑️ 删除该条记忆」操作入口；
- **FR-DEL-3.2 二次防误触确认**：点击后触发二次确认弹窗（明确提示卡片标题与“此操作无法撤销”），用户显式确认后方可发起请求；
- **FR-DEL-3.3 状态联动与反馈**：删除成功后给出绿色 Toast 提示，自动关闭 Modal，并即时从知识列表与态势大盘中移除该条目，无需手动刷新页面。

### 2.4 CLI 命令行快捷删除 (FR-DEL-4)
- **FR-DEL-4.1 命令支持**：支持 `memhub delete <id>` 及别名 `memhub rm <id>`；
- **FR-DEL-4.2 终端确认**：支持交互式确认（`y/n`），并提供 `-y` / `--yes` / `--force` 参数支持脚本化批量静默删除。

---

## 3. 非功能性需求与系统边界 (Non-Functional Requirements)
- **NFR-DEL-1 零残留与无幽灵命中**：删除后执行 FTS5 全文搜索、Vector 语义搜索以及混合检索均无法检索出该条记录。
- **NFR-DEL-2 事务原子性与一致性**：级联三表删除任一环节失败必须整体自动回滚，确保主库、FTS 索引与向量空间严格一致。
